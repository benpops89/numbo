# Bingo Caller — Design

## Intent & Why

A desktop number caller for 90-ball UK bingo. Players mark physical cards; the app
calls numbers aloud with the traditional bingo phrase (e.g. "Two little ducks, 22")
and shows which numbers have been called. Single user, single machine, no networking.

## Goals

- Call each of the 90 numbers at most once per game.
- Speak the number + phrase aloud via pre-generated audio files.
- Show the current call prominently and a 9×10 grid of all 90 numbers with called ones highlighted.
- Manual "Call next" and an auto-call mode with a configurable interval.
- Reset to start a new game.

## Non-goals

- No multiplayer/networking.
- No card generation or win detection (physical cards).
- No persistence of game state across restarts (reset on launch is fine).
- No custom TTS at runtime; audio is pre-generated.

## Constraints

- Framework: MyGo (desktop, Go). Web frontend (Vite/TS) + Go backend services via typed IPC.
- Go 1.27.3+, Bun for frontend tooling.
- Audio: pre-generated WAV files, played by the webview via Web Audio.
- 90-ball UK phrases (one canonical phrase per number).

## Approaches considered

1. **Web frontend + Go backend (chosen).** Rich display via CSS, trivial audio playback, Go owns game logic. Matches requested "backend in Go".
2. **Native UI (all Go).** Lighter but more code for polished display; styling harder. Rejected for display-heavy app.
3. **Electron/other.** Out of scope; user asked for MyGo.

## Design

### Architecture

MyGo app with one window. Go service `Caller` bound via `mygo.Bind`, exposing
methods to the frontend. Frontend is a Vite + TypeScript app.

Events: `Caller.Changed` (broadcast) carries current number, phrase, audio URL,
called set, remaining count, auto state. Frontend subscribes and re-renders.

### Game logic (Go)

- `Caller` holds `remaining []int` (1..90 shuffled) and `called []int` (in order).
- `CallNext() (Call, error)` pops next from remaining, appends to called, broadcasts.
- `Reset()` reshuffles remaining, clears called, broadcasts.
- `SetAuto(enabled bool, intervalMs int)` configures auto-call; runs a goroutine
  ticker that calls `CallNext` while enabled and numbers remain; stops at 90 or
  when disabled. Uses `time.Ticker`; guarded by mutex; broadcasts state changes.
- `State() State` returns snapshot.
- `AudioPath(n int) string` returns relative path to `audio/<n>.wav` (embedded
  as frontend asset / resources).

Shuffle uses `math/rand` seeded with current time.

### Audio

90 WAV files generated by `scripts/gen-audio.sh` using ffmpeg's flite filter:
text = "<phrase>, <number>". Stored in `frontend/public/audio/<n>.wav` (dev) and
embedded into the built app via Vite public dir. Frontend plays via
`new Audio(url).play()`.

### UI (web)

- Header: title "Bingo Caller".
- Main: huge current number + phrase; audio auto-plays on call.
- Grid: 9 rows × 10 cols (1..90), called numbers highlighted.
- Controls: "Call next" button (Space shortcut), "Auto" toggle + interval input
  (seconds), "Reset" button, remaining count.
- Footer: list of last few called (optional).

### Implementation notes

- Bind `Caller` with `mygo.Bind`.
- Auto-call goroutine must not block main thread; broadcast via event.
- Generate TS client with `go run github.com/egoist/mygo/cmd/mygo generate .`.
- Dev: `bun run dev`.
